# Upgrade to Tailwind 4

**Tailwind 4.3.5 through `@tailwindcss/vite`, with the theme in `@theme static` in CSS, unlayered CSS modules on `@reference`, and the Tailwind 3 look kept by compat rules in `global.css`. The site's browser baseline is now Safari 16.4+, Chrome/Edge 111+, Firefox 128+.**

- Date: 2026-11-07
- Alternatives Considered: the official `@tailwindcss/upgrade` tool; keeping the JS config through `@config`; staying on Swiper 12 and Tailwind 3 for older browsers

## Decision

Work `upgrade-2026-11`, slice V7. Visitors must see no change, so every Tailwind 4 default that renders differently from Tailwind 3 was either kept by a compat rule or accepted by the user after a page-by-page diff.

**Setup.** `@import 'tailwindcss' source(none) theme(static);` plus `@source '../';` scans only `src`, as the v3 `content` glob did. The theme moved from `tailwind.config.mjs` into `@theme static`: plain `@theme` only emits the variables a scanned template uses, and CSS modules on `@reference` emit none, so tokens used only through `@apply` in a module (such as `brand-navy-lighter`) would be undefined. The font stacks are defined once, in `@theme`. `tailwind.config.mjs`, both PostCSS configs, autoprefixer and postcss are gone.

**CSS modules.** The 33 modules that used `@tailwind components;` now start with `@reference` to `global.css` and lost their `@layer components {}` wrapper, so their rules stay unlayered as before: inside a native layer they would lose to `swiper/css/bundle`.

**Tailwind 3 behaviour kept** (all in `global.css`): border colour `#e5e7eb`, placeholder colour, button cursor, ring width and colour, `hover` on every device (`@custom-variant hover (&:hover)`); `container` rewritten from the real v3 output (1.5rem padding, 1200px max-width from 1200px only); Tailwind 3 line heights as fixed values; a `v3-space-y-*` utility where children carry their own margins; `a:hover`/`a:focus` kept above single-class colour utilities as v3's specificity did. Renamed because their v4 output differs: `outline-none` → `outline-hidden`, `backdrop-blur-sm` → `backdrop-blur-xs`, `bg-gradient-to-br` → `bg-linear-to-br/srgb`.

**Verification.** Playwright captures of 13 pages at 390, 1024 and 1280 px before and after (pixels, computed styles, hover/focus states, fonts, headings, container probe). After the fix rounds, page heights match Tailwind 3 on 38 of 39 rows (the last differs by 1px). Accepted by the user as same-on-screen rewrites: `oklab` instead of `rgba`, layered shadows, longer transition lists, `space-y`/`divide-y` on the other side, `translate` instead of `transform`, hidden outline written as `none`, and the vendor prefixes Lightning CSS no longer emits. Accepted as is: card links on `/info/la-storia` turn navy on focus, as production already does.

**Browser baseline.** Swiper 14 needs Chrome/Edge/Firefox 110+ and Safari 16.4+ (accepted 2026-11-06; esbuild `es2019` lowers syntax but adds no polyfills). Tailwind 4 raises it to Chrome/Edge 111+ and Firefox 128+ (accepted 2026-11-07). Older browsers may lose carousels and modern CSS features.

## Consequences

No Vercel preview was deployed for V7 (user's call, 2026-11-08): the first Tailwind 4 build on Vercel is the production deploy at the end of the work, where the Node version (24.15+ for jsdom 30) and one `/api/seo-analysis` call are also checked. The compat block is tracked for review at the next redesign (TODO `UP-tw-compat`).
