## The slice, decided here

- **0006 columns, in order** (18): `id INTEGER PRIMARY KEY AUTOINCREMENT`, `code TEXT NOT NULL UNIQUE`, `created_at TEXT NOT NULL`, `email`, `first_name`, `last_name`, `birth_date`, `birth_place`, `address1`, `address2`, `city`, `region`, `postcode`, `country` (all TEXT NULL, so an erased row stays valid), `fee_label TEXT NOT NULL`, `fee_cents INTEGER NOT NULL`, `areas TEXT`, `areas_other TEXT`. `id` stays and is copied: readers address rows by `code`, but `id` is the table's rowid alias, matches `orders`, and dropping it gains nothing. Same rebuild as 0005 (create `_new`, `INSERT … SELECT` with every column named, drop, rename, recreate `membership_requests_created_at`), no `BEGIN`/`COMMIT`.
- **areas_json → areas** in the copy: `(SELECT group_concat(json_extract(j.value, '$.label'), ', ') FROM json_each(m.areas_json) AS j)`, `m` being the old table. `'[]'` gives NULL (no area chosen is NULL, like the other optionals). The one production row is checked by hand (Conductor 3).
- **New rows**: `areas` = the CMS labels of the chosen ids joined by ", ", "Altro" included when ticked, NULL when none; `areas_other` only when "Altro" is ticked. The insert is the only write: no `notify_status` UPDATE. A mail failure is logged as today (`[socio] 200 ok saved=true notified=false notify_error=<E_CODE>`, no request code, no personal data); staff match the log time to `created_at`, and the visitor's lede already asks them to write with the code.
- **Steps markup**: one `<form data-socio-form>`; the error band stays at its top, outside the steps. Two `<section class="socio-step" data-socio-step="1|2" aria-labelledby="socio-step-<n>-title">`. Each opens with `<h2 id="socio-step-<n>-title" class="socio-step__title" tabindex="-1" aria-describedby="socio-step-<n>-count">` and, under it, `<p class="socio-step__count" id="socio-step-<n>-count">Passo <n> di 2</p>`: DESIGN.md's Title Is the Heading Rule puts context below a title, never above. Step 1 is titled "I tuoi dati": the personal fields lose their own fieldset and legend (the section is the group, the birth-data hint stays under the count), "Indirizzo" stays a fieldset, then `<span data-socio-next><Button type="button" primary>Avanti</Button></span>`. Step 2 is titled "Quota": the fee radios keep their fieldset with the legend `MEMBERSHIP_LABELS.fee` ("Tipo di quota", already the summary's name), then the areas fieldset, consent, Turnstile, the send area `<div class="order-send socio-step__nav" data-socio-send>` (`<span data-socio-back><Button type="button" primary={false}>Indietro</Button></span>` and the submit), the failure block, the status line. The inactive step carries the `hidden` attribute, step 2 from the server: it leaves the tab order and the accessibility tree, and the form needs JS anyway (Turnstile).
- **Focus**: Avanti valid → hide the error band, show step 2, focus its h2 (read as "Quota", then its description "Passo 2 di 2"); Indietro → show step 1, focus its h2, hide the error band (its links would point into a hidden step), keep inline errors and values. Enter in a step-1 field submits the form: `onSubmit` on step 1 runs Avanti instead.
- **Errors per step**: `STEP_ONE_KEYS` = email … country; step 2 = fee, areas, areasOther, consent, turnstile. Avanti validates with `validateMembershipFields` and keeps only step-1 keys; the summary lists those. On the final send, a client or server `invalid` with any step-1 key goes back to step 1, sets every returned error inline, and shows the summary of the step-1 keys only (focus on the band); step-2-only keys stay on step 2.
- **Turnstile** loads when step 2 is first shown (no more `focusin` on the form), and on submit as today, so the token is fresh at send.
- **Failure block** (in step 2, after the send area): `<div class="socio-fail" data-socio-fail role="alert" tabindex="-1" hidden>` with `<h3>`, `<p data-socio-fail-text>`, `<span data-socio-retry><Button type="button" primary>Riprova</Button></span>` and a link `Scrivi a info@multimage.org` (`mailtoHref`). Shown, it hides `data-socio-send` and takes focus. It covers: network error, any non-JSON or 5xx answer, `turnstile`, `bad_request`, `too_large`, and `invalid` with no known key. "Riprova" hides it, shows the send area and focuses the submit button; values were never cleared. The widget's own load error keeps today's band message (not a send failure).
- **Preview**: in `index.astro`, `const previewAllowed = import.meta.env.DEV || ['localhost', '127.0.0.1'].includes(Astro.url.hostname)`; `searchParams` is read only inside that condition. When `anteprima` is `conferma` or `errore`, the root gets `data-socio-preview="<value>"`, plus for `conferma` a `data-socio-preview-answer` JSON of a fake `MembershipResponse`: code `SO-000000-PROV` (O is outside the code alphabet, so it never matches a real code), `notified: true`, the first fee (`membershipFeeLabel`, `toCents`), causale from `membershipCausale(paymentNote, code, 'Ada', 'Neri')`. The script then calls the real `showDone` (bonifico stays first) or shows step 2 with the generic failure block; no request is made. In production the hostname is never local and the HTML is byte-for-byte the plain page, which matters because the gateway's cache key is the path only (`src/worker.ts`).
- **Italian texts** (paired forms where gendered; nothing promised beyond today's copy): step titles "I tuoi dati" and "Quota", "Passo 1 di 2", "Passo 2 di 2", fee legend "Tipo di quota", "Avanti", "Indietro", "Riprova". Areas legend "Vuoi anche darci una mano? (facoltativo)", hint "Scegli come ti piacerebbe collaborare e ti scriviamo al più presto." (V4's, without "È facoltativo"), checkbox "Altro", input label `MEMBERSHIP_LABELS.areasOther`. Failure title "La richiesta non è partita"; generic text "Non siamo riusciti a inviare la richiesta. I tuoi dati sono ancora qui: riprova tra poco, oppure scrivici a info@multimage.org."; Turnstile text "La verifica anti-spam non è andata a buon fine. I tuoi dati sono ancora qui: riprova, oppure scrivici a info@multimage.org."; link "Scrivi a info@multimage.org".
- **Tests**: level `essential`, no runner: `npx tsx -e` runs on the lib and local D1 commands, no test files.
