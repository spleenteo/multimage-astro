## Close draft

Narrative: V5 moved the DatoCMS stack to @datocms/cda-client 0.3.2, @datocms/cma-client 6.8.0 and the `datocms` CLI 4.2.0 (cli-utils 4.2.1, one rest-client-utils 6.10.1 copy), removing the `@datocms/cli-utils` override (UP-cli-utils-override closed). No `src` file needed a change: the type shims were already gone since V3, so `astro check` now checks `reindex`, `rawFind` and `plugins.*` against the real v6 types, and T3 matched them to `cma:docs`, the 5.8.1 d.ts and the release notes. A before/after probe showed a CDA 401 through `handleUnexpectedError` echoing the token on 0.2.10 and not on 0.3.2. `schema.ts` regenerated with CLI 4.2 is a pure reorder (same 39 types, same ids). The dev smoke found two things the plan didn't foresee: in dev Vite answers every OPTIONS with its own 204, so the route-load check became a GET (our OPTIONS handlers wait for the V7 preview); and the local `.env` has `DATOCMS_CMA_TOKEN` empty, so `/api/seo-analysis` 500s locally — the real `rawFind` ran with the token mapped from `DATOCMS_API_TOKEN` in the server's process env only, and a CMA 404 came back as a 500 with `authorization` REDACTED and no token in body or log. The final review recorded the `DATOCMS_CMA_TOKEN` docs drift as TODO UP-cma-token-docs (runtime variable on Vercel for the reindex and seo-analysis; the `.env.example` comment is the user's). Still open from V5: a `/api/post-deploy` 500 can carry `SECRET_API_TOKEN` in the echoed CMA `request.body` (S5, now in security.md).
Lessons:
- In a leak probe, guard each needle (`v ? body.includes(v) : 'unset'`): a variable present but empty in `.env` loads as `""`, and `includes("")` is always true.
- In `astro dev`, Vite answers every OPTIONS request with its own 204 before the route runs: prove a route module loads with a GET (404 or 401), and leave the OPTIONS handlers to a deploy.
- On TypeScript 6, a standalone `tsc <file>` with flags fails with TS5112 when a `tsconfig.json` is present: add `--ignoreConfig`.
- Before a smoke that needs a server-side token, check that it is non-empty in the env the server reads (names and emptiness only, never values); a local `.env` can hold the name with no value.
