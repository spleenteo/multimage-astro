## The slice, decided here

- **Versions come from `npm view` on 2026-11-05**: @datocms/cda-client 0.3.2, @datocms/cma-client 6.8.0, `datocms` 4.2.0 (it needs cli-utils ^4.2.0 → cma-client-node 6.1.3 → cma-client ^6.1.3, rest-client-utils ^6.1.0). If a newer patch shows up at run time, the executor takes it and says so. The CLI moves from `~4.0.29` to `^4.2.0`: the tilde was only there for the override.
- **The `overrides` block goes first**: with `@datocms/cli-utils <4.2.0` still in place, `datocms` 4.2 cannot resolve. This closes TODO UP-cli-utils-override.
- **No change planned in `executeQuery.ts`**: the 0.3.2 `BuildRequestHeadersOptions` (token, includeDrafts, excludeInvalid, environment, contentLink `'v1' | 'vercel-v1'`, baseEditingUrl) is identical to 0.2.10. 0.3.0 adds an `exports` map, `.js` ESM specifiers and an `ApiError` that `instanceof` now matches (before, it never did); 0.3.1 redacts `options.token` and makes `query`/`options`/`response` non-enumerable; 0.3.2 adds retry jitter.
- **cma-client 6 breaks only `uploads` simple methods** (`default_field_metadata` shape, 6.0.0), which this repo does not call. `reindex(buildTriggerId)`, `items.rawFind(id)` and `plugins.rawList/create/update` have the same signatures in 6.8.0 as in 5.8.1. rest-client-utils 6.1.1 redacts the `authorization` header in `ApiError.request` and makes `request`/`response` non-enumerable. `utils.ts:31-32` reads them explicitly, so a CMA 500 still returns them, with the header redacted.
- **`utils.ts` stays as it is**: `ApiError` comes from cma-client, and its brand (`Symbol.for('@datocms/rest-client-utils:ApiError')`) differs from cda-client's, so a CDA error still goes to `serializeError`. On 0.3.x, `serializeError` no longer sees `options`.
- **Type shims**: there is nothing left to delete (see Deviations). T1 checks that no `declare module '@datocms…'` remains and removes the empty, untracked `src/types/` directory.
- **No preview deploy**: the mandate's Done names only the gate and the dev smoke, and V7 ends with the final preview. `reindex` and `plugins.*` are never called for real, because they would reindex the production search or rewrite the production plugins. They are checked against the docs and by `astro check`.
- **Test level essential, no test file**: no test runner exists, and no behaviour changes in the sensitive areas. The proof is the probe (T1), `astro check`, and the T4 runtime checks.

## Deviations from the mandate

- The type shims were already deleted in V3 (commit 858c5da, cma-client 5.8 broke them) and `src/types/` is empty. V5 only checks that no `declare module '@datocms…'` is left and removes the empty directory.
- No preview deploy, and `reindex` and `plugins.*` are not run, because both would touch production. They are checked against the docs (T3) and by types. Their first real run is the end-of-work procedure (c) on production.
- Beyond the named dev smoke, T4 runs one read-only `rawFind` through `/api/seo-analysis` and a CMA-error 500, and T1 proves the redaction with a before/after probe. Without them, the token Done and the CMA v6 runtime would rest on types alone.
- The removal of the `@datocms/cli-utils` override and the closing of TODO UP-cli-utils-override come from `dependencies.md`/`TODO.md`, not from the slice text: CLI 4.2 cannot install while the override is in place.
- T5 also edits `security.md` (the CMA `authorization` header and CDA options are redacted; `request.body` is still echoed, so a `/api/post-deploy` 500 can carry `SECRET_API_TOKEN`, S5) and the TODO D4-R5 line (cda-client 0.3.0 changes `instanceof ApiError`).
