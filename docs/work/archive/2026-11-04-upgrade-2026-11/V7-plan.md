## The slice, decided here

- **Versions** (`npm view`, 2026-11-07): `tailwindcss` and `@tailwindcss/vite` 4.3.5. The plugin's peer is `vite ^5.2 || ^6 || ^7 || ^8`, and Astro 7.4.7 runs Vite 8.3.6. Both packages go in `dependencies`, where `tailwindcss` is today. A newer 4.3.x at run time is taken and reported.
- **`postcss` and autoprefixer go, and both PostCSS configs are deleted.** The configs hold only the two removed plugins, and nothing else imports `postcss`. Deleting both also settles which file Vite loads. `tailwind.config.mjs` is deleted: its theme moves to `@theme`.
- **Every theme variable is always emitted.** v4 writes a theme variable to `:root` only when a scanned utility uses it. `@reference` modules emit no variables, and the scanner skips CSS files. So tokens used only through `@apply` in modules would stay undefined: `bg-brand-navy-lighter` (`BookCarouselSection/style.module.css:5`), `max-w-*`, `text-*` and `leading-*`. The fix: the project tokens go in `@theme static {}`, and the import becomes `@import 'tailwindcss' source(none) theme(static);`. This adds a few KB of CSS, which is a cached static asset.
- **Only `src` is scanned for classes**: `source(none)` on the import, plus `@source '../';`, the same scope as the v3 `content` glob. Without it, v4 also scans `docs/`, `scripts/` and `schema.ts`.
- **The font stacks are defined once, in `@theme static`**, with today's `:root` values: `--font-sans: 'Inter', system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;` `--font-serif: 'Playfair Display', 'Times New Roman', serif;` Both leave `:root`. The v3 utility added a tail (`Inter, system-ui, sans-serif`) that only repeated families already in the stack, so the font that renders first is unchanged. `/libri/schede/[slug]` reads `var(--font-sans)` and `var(--font-serif)`, which are now always emitted.
- **Theme tokens**: `--color-brand-<key>` and `--color-social-<key>` for every key in `tailwind.config.mjs`, with the same hex values. `--shadow-soft`, and `--tracking-wide: 0em; --tracking-wider: 0em;`. Radius: `--radius-*: initial;`, then `--radius`, `--radius-none`, `-xs`, `-sm`, `-md`, `-lg`, `-xl`, `-2xl`, `-3xl` and `-full`, all `0px`. v4 reads `rounded-full` from the theme before falling back to its built-in `calc(infinity * 1px)` (read in tailwindcss 4.3.3 `dist/lib.mjs`), so bullets and pills stay square.
- **`container` is rebuilt from the real v3 output, not from the config.** The current build gives `width:100%`, auto margins and 1.5rem padding, plus `max-width:1200px` only at ≥ 1200px. The sm and lg paddings in the config never applied, because v3 maps paddings only onto `container.screens`. v4's built-in `container` sets a max-width at every breakpoint, so the rewrite is `@utility container { margin-inline: auto; padding-inline: 1.5rem; @media (width >= 40rem) { max-width: none; } @media (width >= 1200px) { max-width: 1200px; } }`. This follows the container compat code of the official upgrade tool. The probe checks it at 768, 1024, 1199, 1200, 1280 and 1600 px: `none` up to 1199, `1200px` from 1200, and 24px padding everywhere.
- **v3 defaults are kept**, so visitors see no change: At the top of `@layer base`: `*, ::after, ::before, ::backdrop, ::file-selector-button { border-color: #e5e7eb; }`, `input::placeholder, textarea::placeholder { color: #9ca3af; }` and `button:not(:disabled), [role='button']:not(:disabled) { cursor: pointer; }`. In `@theme static`: `--default-ring-width: 3px; --default-ring-color: rgb(59 130 246 / 0.5);`. `@custom-variant hover (&:hover);`, because v4's `hover:` only matches devices with `(hover: hover)`.
- **The shadow scale needs no rename**: `src` uses no `shadow-sm` or `shadow-xs`, and the bare `shadow` and `backdrop-blur` keep their v3 values through v4's deprecated `--shadow` and `--blur`. T3 renames three utilities whose v4 output differs: `outline-none` → `outline-hidden` (19 uses); `backdrop-blur-sm` → `backdrop-blur-xs` (8 uses; v4's `-sm` is 8px); `bg-gradient-to-br` → `bg-linear-to-br/srgb` (2 uses; v4 interpolates in oklab).
- **CSS modules**: 33 files open with `@tailwind components;` and wrap all their rules in one `@layer components {}`. They get `@reference '<relative path to src/styles/global.css>';` and lose the wrapper, so their rules stay unlayered as today. Inside a native layer they would lose to `swiper/css/bundle`. The 4 plain modules (`PillsBlock`, `BannerSection`, `FeaturedBookHighlight`, `pages/index`) have no Tailwind directive and are not touched. `@reference` drops the Google Fonts `url()` import, because Tailwind skips `http(s)` imports and outputs nothing from a referenced file. T4 checks this on the built CSS.
- **Known cascade changes, judged by the diff, not by argument**: v4 utilities live in `@layer utilities`, so any unlayered rule (module CSS, `_search.css`, Swiper) now beats a utility on the same element, whatever the source order. Example: PillsBlock's `.card { transition: transform…, background-color… }` (`PillsBlock/style.module.css:1-5`) now always beats the `transition` utility on the same `<article>` (`PillsBlock/index.astro:77-79`). `space-y-*` now uses `margin-block-end` inside `:where`. `translate-*`, `scale-*` and `rotate-*` now set the separate `translate`, `scale` and `rotate` properties, which add up with any `transform:` on the same element. The static pass and the hover/focus pass report these. Nothing is fixed in advance.
- **The visual check is a machine diff, and the user judges it.** It uses the global Playwright 1.60 with the cached Chromium 1243 (not a project dependency). Screenshots are taken in 4000 px tiles, so tall pages (`/libri` and `/autori` at 390 px) never hit Chromium's size limit or compare blank areas. They are compared pixel by pixel on a canvas in the same browser, so no new package is needed. A computed-style dump of every element. A hover pass and a focus pass, with focus forced through CDP `CSS.forcePseudoState`. A heading summary. Runs: dev before vs dev after, then preview vs production. T1 captures twice to get the noise floor.
- **The conductor runs the server, browser and deploy work (T1, T4, T5)**, as in V6. The dev server uses port 4337 (never 4321 or 4329), with `SITE_SEARCH_BUILD_TRIGGER_ID=` empty in the process env. Local requests are GET only.
- **Test level essential, no test file**: no sensitive area is touched (CSS, config and templates only).
