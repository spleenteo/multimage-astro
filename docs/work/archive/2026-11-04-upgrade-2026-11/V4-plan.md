## The slice, decided here

- **Versions are from `npm view` on 2026-11-05**: astro 7.4.5 (engines node >= 22.23.4; local is 24.18), @astrojs/vercel 11.0.18 (peer `astro ^7`). @astrojs/check 0.9.12 and @astrojs/ts-plugin 1.10.12 are already the latest and declare no astro peer, so they stay. If `npm view` shows a newer patch at run time, the executor takes it and says so.
- **Manual install, not `npx @astrojs/upgrade`**: the tool prompts interactively, and the guide allows the manual path. The guide's checklist applied to this repo: there is no `src/fetch.ts`, no `experimental` block, no `.md`/`.mdx`, no `astro:transitions` internals, no `getContainerRenderer`, no `@astrojs/db`, no Vite config. So only the Rust compiler and `compressHTML` apply.
- **`compressHTML: true` is pinned** (mandate), so there is no `{" "}` audit. The DOM diff in T1/T4 shows that no whitespace or nesting change reaches visitors, which is what the guide's "visually inspect" step asks.
- **`@datocms/astro` 0.6.16 is the latest** (peer `astro: *`). It imports only `astro:components`, `astro/jsx-runtime` and `navigate` from `astro:transitions/client`, and Astro 7 still exports all three. Its components compile under the Rust compiler at build time, and T4/T5 render Image, StructuredText and QueryListener.
- **The ISR block in `astro.config.mjs` stays as it is**: adapter 11 keeps the option names. Expected output, read from the 11.0.18 source: `allowQuery: ["x_astro_path","x_astro_path_token"]`; every `/_isr` route has its `src` wrapped as `^(…)$` and its dest becomes `/_isr?x_astro_path=$1&x_astro_path_token=<uuid>`; the `/_astro/(.*)` cache header moves before the `filesystem` handle (#18008). The token is a `crypto.randomUUID()` per build: it is redacted in every comparison and never stored.
- **No code change in `src/middleware.ts`, `src/lib/draftMode.ts` or the draft-mode endpoints**: nothing in the guide touches them. `AstroCookieSetOptions` now includes `partitioned` natively, so the cast in `draftMode.ts` becomes harmless and stays (removing it would be a refactor). Their behaviour is checked through cookie names and attributes (T4, T5).
- **Test level essential, no test files**: no code in a sensitive area changes. The proof is the commands below.
- **Own dev server with `--ignore-lock`**: Astro 7 `astro dev` backgrounds itself under an agent and writes a lock in `.astro/`. `--ignore-lock` runs a one-off foreground server that neither takes nor checks the lock, so it never clashes with the user's 4321.
- **The preview is reached without handling secrets by hand**: with protection on, `vercel curl` reads an existing automation bypass itself. If none exists, it would create one on the project, so that case stops and asks the user.
- **`/api/revalidate` on the preview**: a non-no-op call is allowed only if the preview's canonical origin is the preview URL **and** `SITE_SEARCH_BUILD_TRIGGER_ID` is absent from the Preview env, because a non-no-op call also reindexes the production search. Otherwise only `app-publish.json` (a no-op).
