## The slice, decided here

- **The default `query` is a lazy import**, not a static `query = executeQuery`. `executeQuery.ts` imports `astro:env/server`, which tsx cannot load: a static import would keep the hooks. `revalidationUrls.ts` gets `type RevalidationQuery = <R>(query: string, options: { variables: Record<string, unknown> }) => Promise<R>` and a module-level generic default `const defaultQuery: RevalidationQuery = <R,>(q: string, o: { variables: Record<string, unknown> }) => import('./executeQuery').then((m) => m.executeQuery<R>(q, o))` (spelled generic, or it returns `Promise<unknown>`). The endpoint passes no query, so it behaves as today. Vite may warn that `executeQuery.ts` is both dynamically and statically imported: T2 checks the `npm run build` output and either avoids the warning or records it here as accepted, with the reason.
- **Index paths live once**: `INDEX_PAGE_PATHS` (`libri`→`/libri`, `ebooks`→`/libri/ebooks`, `highlights`→`/libri/highlights`, `archivio`→`/libri/archivio`, `collane`→`/collane`, `autori`→`/autori`, `magazine`→`/magazine`, `distributori`→`/distributori`) is exported from `recordInfo.ts` (no imports, safe for tsx) and read by both maps. This narrows gap #13. Slugs are taken from the `allIndexPages(filter: { slug: { eq: … } })` queries in each index route.
- **`index_page` `libri`** also feeds `/libri/pagina/[page]` (`BOOKS_PAGE_QUERY` reads `booksIndexPage`), so it adds the catalogue pages via a count-only query aliased `catalogueBooksMeta: _allBooksMeta(…) { count }` (same filter as `BOOK_CONTEXT_QUERY`; the stub returns that alias). On failure it falls back to `/libri` and logs a line containing `enrichment failed`. An unknown slug returns `[]` (no-op). No sitemap: `sitemap.xml.ts` lists index paths with no `lastmod`.
- **`supplier`** → `/distributori` in both maps (the Web Previews plugin can then link the supplier list).
- **`license`** has no slug. The license is **rendered only on the book page** (`buildEditionDetails`, `src/lib/books.ts:277`, used by `/libri/[slug]` and the staff sheet); `BookCard` declares a `license` prop but never renders it, and `FeaturedBookHighlight` has none — the card fragments fetch it without showing it (this overturns V1's "license on every book card route"). So the payload's `entity.id` (now returned by `parseWebhookPayload`) feeds `allBooks(filter: { license: { eq: $id } }, first: 500) { slug }` (`// TODO CD2`), and the URLs are only each book's `/libri/<slug>`. No catalogue count, no listings, no authors or collections. On failure: `[]` and a log line containing `enrichment failed`. Link-filter syntax: copy the existing pattern `BOOK_COLLECTION_BOOKS_QUERY` (`src/pages/libri/[slug]/_graphql.ts:139-145`: `$collectionId: ItemId`, `collection: { eq: $collectionId }`), never from memory.
- **`app`** → explicit `[]` with a comment. Its only reader, `/libri/schede/[slug]`, is staff-gated: a revalidation fetch has no session, gets the middleware 404, and editors bypass the cache anyway.
- `recordInfo.ts` maps no route for `license` or `app` (no page of their own). `recordToSlug` is unchanged.
- **The commits split by kind**: T2 is the refactor (no behaviour change, the old check still passes), T3 is the feature plus its check, T4 is the cleanup.
- **The (b) run uses its own server on a free port** (Dev servers rule), never 4321. Procedure (b) in `caching.md` is rewritten the same way.
