## The slice, decided here
- **Endpoint order** after the existing checks (config, size, JSON, fields, Turnstile, CDA rebuild with the `ITEM_ID` pre-filter kept): build the code → INSERT (`notify_status 'pending'`) → `ORDER_MAIL.send` → UPDATE `notify_status`/`notify_error`. Outcomes: saved + sent → 200; saved + mail failed or no `ORDER_MAIL` → 200, row `failed` (error code) or `skipped` (`no_binding`); not saved + sent → 200 (the email carries the whole order); not saved + not sent → 502 `save_failed`; no `ORDERS` and no `ORDER_MAIL` outside dev → 503 `not_configured` at step 1, before the body is read. No Turnstile secret outside dev stays 503.
- **Dev without bindings** (plain `npm run dev`, stub): the email text goes to the console inside an `if (import.meta.env.DEV)` block of its own (lesson), answer 200 with a real-format code and `notified: false`. Dev with bindings (`DEPLOY_TARGET=cloudflare` dev) takes the real path against local D1 and the simulated `send_email`.
- **Order code** `MM-YYMMDD-XXXX`: UTC date, four characters from the 32-letter alphabet `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (no 0/1/I/O), one random byte each (`byte % 32`, no bias). About a million codes a day: a UNIQUE clash fails the insert, the email still goes, so no retry loop.
- **Row**: 18 written columns in `ORDER_COLUMNS` order (`id` autoincrement, `notify_error` NULL); `phone` and `notes` NULL when empty; `created_at` = `consent_at` = one `toISOString()`; `lines_json` = the server-rebuilt `OrderLine[]` (`id, slug, title, authors, priceCents, qty, amountCents`). CHECKs on `shipping_kind`, `buyer_kind`, `notify_status` (`pending|sent|failed|skipped`) and `json_valid(lines_json)`; index on `created_at`. No staff `status` column (the staff app adds it by migration).
- **SQL** is built once at module scope from `ORDER_COLUMNS` with `?1…?18` placeholders; values only through `.bind()`.
- **Mail**: `send({ from: { email: ORDER_FROM_ADDRESS, name: ORDER_FROM_NAME }, to: ORDER_EMAIL, replyTo: order.email, subject, text })`. `notify_error` stores only a code matching `^E_[A-Z0-9_]{1,60}$`, else `unknown`. The binding also gets `allowed_sender_addresses: ["sito@ordini.multimage.org"]` (spike A5).
- **D1 placeholder id** `00000000-0000-0000-0000-000000000000`, commented as a placeholder: never empty (wrangler would auto-provision outside the EU), and a deploy with it fails.
- **Types**: the wrapper declares minimal local interfaces (`prepare().bind().run()`, `send()`); `src/cloudflare-workers.d.ts` declares `module 'cloudflare:workers' { export const env: Record<string, unknown> }` (outside `src/lib`, so it is not read as the wrapper's own declaration). No Workers types are installed.
- **Logs**, counts and codes only: `[ordine] 200 ok lines=<n> dropped=<n> saved=<bool> notified=<bool>` (+ ` notify_error=<code>`), `[ordine] save_error`, `[ordine] 200 ok (dev) lines=<n> dropped=<n>`. Never a name, email, address, notes, token, or a D1 error message.
- **Wording stays for V5**: the client only swaps `copySent` for the code (lede "L'abbiamo girato a Olivier. Il codice del tuo ordine è <b>code</b>." and the print button always shown); `index.astro`, `EMAIL_EMPTY_MESSAGE` and the docs (`security.md`, `operations.md`, …) are V5's.
- **Tests (essential)**: pure logic by `npx tsx "$TMPDIR/borsa-V4/order-check.ts"` (absolute import, `node:assert/strict`); the table by a local migration into `$TMPDIR`; the endpoint by curl (T4 plain dev, T6 Cloudflare dev and a production-mode Worker). Dev servers on a free port (`lsof -nP -iTCP:<port> -sTCP:LISTEN` empty; never 4321, 4322, 4329, 5198), logs in `$TMPDIR/borsa-V4/`, stopped by PID, then `git diff --quiet -- schema.ts || git checkout -- schema.ts`. Valid bodies are written by python from one template: a real book id read from the `data-bag-item` attribute of a priced book page, buyer `probe-v4@example.invalid`, `turnstileToken: 'XXXX.DUMMY.TOKEN.XXXX'`.
