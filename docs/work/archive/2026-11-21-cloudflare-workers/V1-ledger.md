## Close draft
Narrative: V1 put Workers Cache in front of the trial Worker. A custom entry `src/worker.ts` runs a cache-off default gateway that forwards every request to a cache-on `Backend` entrypoint through `ctx.exports.Backend.fetch`: path-only `cf.cacheKey` outside `/api`, `cache: 'no-store'` when the draft cookie is present. The middleware applies the route → policy table behind `context.cache.enabled` (60-day `maxAge`, body buffered only on cached rows, `private, no-store` elsewhere), and `cacheCloudflare()` is wired only under `DEPLOY_TARGET=cloudflare`. The flagged part held: `ctx.exports` and per-entrypoint cache worked on the first deploy, with no `enable_ctx_exports` flag and no fallback Worker. On the trial Worker, `/` and a book page went MISS then HIT, HITs never reached `Backend` (confirmed by wrangler tail), `?utm_source` shared the entry, the draft request was DYNAMIC and private while the anonymous copy stayed a HIT, and `/staff`, `/api/draft-mode/disable` and `/libri/pagina/999` were BYPASS every time. The T2 review caught a Vercel regression: reading the draft flag once, before `next()`, flipped the CSP on the draft-mode endpoints, because Astro's cookies return the values set during the request. It is now read again after `next()`. `/robots.txt` is a static asset served by Workers Assets and was a HIT both times, outside the middleware's reach, as the plan expected. The lint gate went red on the git-ignored `.wrangler/deploy/config.json`; `.wrangler/` is now prettier-ignored. Rulings: the packet went to the agents as a file path, not pasted inline.
Lessons:
- In Astro middleware, read any cookie-derived flag after `next()` when the response depends on it: `context.cookies.get()` returns the cookies the endpoint set or deleted during the request, so a value read before `next()` is stale on the endpoints that change it.
- Files under `public/` are served by Workers Assets before the Worker runs: the middleware's cache policy never applies to them, and they leave no `wrangler tail` event. Check them with `_headers`, not the middleware.
- Every Cloudflare build rewrites `.wrangler/deploy/config.json`: keep `.wrangler/` in `.prettierignore` so `npm run lint` stays green after `build:cf`.
Decision candidate: Cloudflare cache gateway as a second entrypoint of the same Worker (`ctx.exports.Backend`, per-entrypoint `cache` in `wrangler.jsonc`) rather than a separate gateway Worker with a service binding; it works with the Astro 7 / @astrojs/cloudflare 14 build as is, and purges (V2) must run in `Backend`.
