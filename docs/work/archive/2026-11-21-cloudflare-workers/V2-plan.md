## The slice, decided here

- **Purge through `locals.cfContext.cache.purge`, no `cloudflare:workers` import.** `handle()` puts the Backend's `this.ctx` in `locals.cfContext` (`@astrojs/cloudflare/dist/utils/cf-helpers.js:42`), and Cloudflare documents `ctx.cache.purge()` and `cache.purge()` as equivalent, same result `{ success, errors[{code, message}] }` (`cfdocs/cache_purge.md` "Two ways", "Return value"). A literal `import('cloudflare:workers')` in a route bundled for Vercel fails: Vite throws on `UNRESOLVED_IMPORT` (`vite/dist/node/chunks/node.js:34877`), its SSR builtins are only `node:`/`bun:`; and no Workers types are installed, so `astro check` would fail too. No `.d.ts` in `node_modules` types `purge`: `cacheInvalidation.ts` declares the minimal shape from the docs. The call runs in `Backend`, the entrypoint whose cache it purges.
- **Store**: `AsyncLocalStorage` from `node:async_hooks` (`nodejs_compat` is on in `wrangler.jsonc`). The middleware opens it only when `context.cache.enabled`, for GET outside `/api` and internal paths; `next()`, the CSP step and `arrayBuffer()` all run inside `store.run`, so the layout query, which runs while the body streams, lands in it. On Vercel there is no store: `executeQuery` and the middleware run as today.
- **Tag order and limit**: `AstroCache.set` keeps tags in insertion order (`astro/dist/core/cache/runtime/cache.js`); the provider appends `astro-path:<path>` last (and a version tag only with `CF_VERSION_METADATA`, not bound). Cloudflare keeps 1000 tags per response, printable ASCII `0x21–0x7E`, 1024 chars each, and drops invalid ones silently (`cfdocs/cache_configuration.md:538-545`). `MAX_PAGE_TAGS = 990`.
- **Coarse fallback**: tags `['site']` and `maxAge` `COARSE_MAX_AGE = 86400` (1 day) when the unique tags are 0, over 990, any tag is invalid (outside `0x21–0x7E` without `,`, the provider's separator, or over 1024 chars), or an HTML page has no layout tag. Each of these would leave a page unpurgeable for 60 days; `site` goes into every purge, so these pages refresh on any change, and one day bounds a lost webhook. Logged with `console.warn`.
- **Layout label**: `executeQuery` gets an optional `cacheTagScope?: 'layout'`; only BaseLayout passes it. The other callers keep the same call; `excludeInvalid`, `contentLink`, `environment` unchanged.
- **Draft**: a draft query marks the store `disabled`; the middleware then takes the private row (double check with `draftNow`).
- **Endpoint order**: 401 (secret unset or bearer mismatch) → 400 (bad JSON, or `entity.attributes.tags` not an array of non-empty strings) → 503 (`cache.enabled` false or no `cfContext.cache`) → purge. Empty `tags` → 200 `noop`. Purge calls run in sequence and stop at the first `success: false` or throw → 502 (DatoCMS `auto_retry` resends the whole call). Success → `reindexSiteSearch('[invalidate-cache]')`. The middleware already makes `/api/*` private.
- **Tests (essential)**: the helpers live in `src/lib/datocms/`, a sensitive area, so T1 adds the check; `executeQuery`, the middleware and the endpoint are covered by `astro check`, the build and T6.

## Deviations from the mandate

- Purge through `locals.cfContext.cache.purge` (the Backend's `ctx`) instead of `cache.purge` imported from `cloudflare:workers`: the import breaks the Vercel bundle and `astro check`; Cloudflare documents both as equivalent, with the same result to check.
- Done 4 `hasLayoutTags: true` cannot hold for `/sitemap.xml` and `/archived-books.json`: they are endpoints and render no BaseLayout. For them the check is `tagCount` > 0 and `coarse: false`.
- The coarse `site` fallback also covers zero tags, an invalid tag and an HTML page without layout tags, besides overflow: each would leave a page unpurgeable for 60 days.
