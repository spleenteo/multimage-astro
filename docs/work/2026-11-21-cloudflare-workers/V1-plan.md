# V1 plan — Cache in front of the Worker, editors bypass it

**Mandate**: [slices.md § V1](slices.md#v1--cache-in-front-of-the-worker-editors-bypass-it) · **Guidelines**: [development-guidelines.md](../../development-guidelines.md), [caching.md](../../guidelines/caching.md), [preview-mode.md](../../guidelines/preview-mode.md), [security.md](../../guidelines/security.md), [operations.md](../../guidelines/operations.md), [dependencies.md](../../guidelines/dependencies.md) · **Lessons**: none yet · **Execution rules**: [executor.md](/Users/spleenteo/.claude/plugins/cache/flow/flow/facb0e621782/agents/executor.md) · **Shape facts**: [shaping.md](shaping.md#facts-that-constrain-the-shapes)

**Summary**
1. T1: `cacheCloudflare()` provider under `DEPLOY_TARGET=cloudflare` only; a custom Worker entry `src/worker.ts` (cache-off gateway `default` + cache-on `Backend` wrapping `handle`); `main`, `cache` and `exports` in `wrangler.jsonc`; the worker file kept out of `astro check`.
2. T1 proves the build side: `build:cf` green, the generated `dist/server/wrangler.json` keeps `cache` and both `exports`, `wrangler deploy --dry-run` accepts it.
3. T2: the middleware applies the route → policy table (`maxAge` 60 days, no tags), buffers only the cached rows, all of it behind `context.cache.enabled`.
4. T3 (conductor): deploy to the trial Worker and run Done 1–4 with `curl` and `wrangler tail`. Done 5 is the gate plus `build:cf`.

**Files**: astro.config.mjs, src/worker.ts (new), wrangler.jsonc, tsconfig.json, src/middleware.ts

## The slice, decided here

- **The gateway fits the adapter's build; no fallback needed.** Read in the installed code: `cloudflareConfigCustomizer` keeps a user `main` (`main: config.main ?? "@astrojs/cloudflare/entrypoints/server"`, `dist/wrangler.js`) and adds `cache: {enabled:true}` only when `cache.enabled` is undefined; `@cloudflare/vite-plugin` 1.70.1 builds `main` through a virtual entry that does `export * from <user entry>` plus `export default mod.default`, so the named `Backend` class survives; `getOutputConfig` spreads the whole input config into `dist/server/wrangler.json` (today's output already carries `exports: {}`), so `cache` and `exports` pass through; the prerender worker config drops `exports` and forces the stock `main`, so it is unaffected. Schema (`wrangler/config-schema.json`): top-level `cache: {enabled, cross_version_cache?}`; `exports.<name>: {type:"worker", cache:{enabled}}`, `"default"` = default export (Cloudflare docs, per-entrypoint caching, wrangler ≥ 4.107; installed 4.147).
- **`ctx.exports` needs no flag**: workerd's flag table has `enable_ctx_exports` default-on from 2025-11-17; `compatibility_date` is 2026-11-01. If T3 shows `ctx.exports` undefined, add `"enable_ctx_exports"` to `compatibility_flags` and say so.
- **`handle(request, env, ctx)`** from `@astrojs/cloudflare/handler` is exactly what the stock entry exports (`export default { fetch: handle }`); `Backend.fetch` calls it with `this.env`, `this.ctx` (it uses `ctx.waitUntil` and puts `ctx` in `locals.cfContext`).
- **Cache key**: outside `/api` (`pathname === '/api' || startsWith('/api/')`) the gateway sets `cf: { cacheKey: url.pathname }`. Grep: no server code reads the query string; `BaseLayout.astro:66` clears `url.search` for the canonical, and `cerca/search-page.client.ts` reads `?q` in the browser only.
- **Draft bypass**: cookie presence only, name `env.DRAFT_MODE_COOKIE_NAME?.trim() || 'multimage_draft_mode'`, parsed from the `Cookie` header (`;`-split, trimmed, `name=` prefix). Present → `{ cache: 'no-store' }` and no `cacheKey`.
- **Types: `src/worker.ts` is excluded from `astro check`** (`tsconfig.json` `exclude`). Neither `@cloudflare/workers-types` nor a `wrangler types` file is installed; either one puts the Workers runtime globals (`Request`, `Response`, `fetch`) into the same program as the DOM lib, which risks breaking type checks across the Astro code on the Vercel build, and needs a second tsconfig plus a large generated file for a ~40-line entry. Nothing imports the file, so excluding it removes it from the check. The bundler strips its types; T1's build and T3's deploy check it. A comment at the top of the file says so.
- **Policy, read from Astro 7.4.7**: `handleCache` applies the provider headers after the middleware returns, so a new (buffered) `Response` gets them; with the provider on, the adapter sets `Cloudflare-CDN-Cache-Control: no-store` on any response without that header (`utils/response.js`), so `set(false)` is never cached by default. "GET" means GET only: a HEAD on a cold cache reaches the Worker as GET (Workers Cache limits), so `curl -sI` still warms the entry.
- **`/robots.txt` is `public/robots.txt`, a static asset**, and no `/llms*.txt` route exists: the "endpoints with no CDA query" row has no Astro route today. The row stays in code (anything not cached is `set(false)`); the Done 4 check still runs on `/robots.txt`, as an observation only (see Deviations).
- **Buffered rows set no cookie**: outside `src/pages/api/` no code calls `cookies.set`/`delete` (only `draftMode.ts`, used by the API routes). No tags in V1, no `CF_VERSION_METADATA`.
- **No test file**: essential level, but no runner is configured; `src/middleware.ts` is covered by the gate and T3.

## Tasks

### T1 — Cache provider and gateway Worker entry (critical)
**What**: (a) `astro.config.mjs`: `import { cacheCloudflare } from '@astrojs/cloudflare/cache';` and add `...(isCloudflare ? { cache: { provider: cacheCloudflare() } } : {})` to `defineConfig` (Vercel: no `cache` key, as today). (b) New `src/worker.ts`: `import { WorkerEntrypoint } from 'cloudflare:workers'; import { handle } from '@astrojs/cloudflare/handler';` — `export class Backend extends WorkerEntrypoint { fetch(request: Request) { return handle(request, this.env, this.ctx); } }`; `export default { async fetch(request, env, ctx) { … } }` that computes the cookie name, checks presence, and returns `ctx.exports.Backend.fetch(request, init)` with `init = { cache: 'no-store' }` when the cookie is present, else `{ cf: { cacheKey: url.pathname } }` outside `/api`, else no init. Header comment: gateway role, the cookie-name rule copied from `src/lib/draftMode.ts:9` (keep in sync; the worker cannot import `astro:env`), why the default entry is cache-off, double draft bypass with the middleware, excluded from `astro check` (reason above). No other logic (no `noindex`, no header rewrites). (c) `wrangler.jsonc`: `"main": "./src/worker.ts"`, `"cache": { "enabled": true }`, `"exports": { "default": { "type": "worker", "cache": { "enabled": false } }, "Backend": { "type": "worker", "cache": { "enabled": true } } }`, each with a one-line comment. (d) `tsconfig.json`: add `"src/worker.ts"` to `exclude`.

### T2 — Route → policy table in the middleware (critical, depends on: T1)
**What**: In `src/middleware.ts` add `SIXTY_DAYS = 60 * 60 * 24 * 60`, `CACHED_NON_HTML_PATHS = new Set(['/sitemap.xml', '/archived-books.json'])`, `isApiPath(pathname)`, and `withHeader(response, name, value)` that sets the header and, if `set` throws (immutable headers), returns `new Response(response.body, response)` with it set. Compute `draft = isDraftModeEnabled(context.cookies)` once. Internal-path 404: when `context.cache.enabled`, call `context.cache.set(false)` and return it with `Cache-Control: private, no-store`; otherwise return it as today. After `next()` and the existing CSP step (unchanged), `if (!context.cache.enabled) return response;`, then one decision: (1) private — `draft`, internal path, API path, `method !== 'GET'` or `status !== 200` → `cache.set(false)` + `withHeader(…, 'Cache-Control', 'private, no-store')`; (2) cached — GET 200, no draft, and `content-type` starts with `text/html` or the path is in `CACHED_NON_HTML_PATHS` → `const body = await response.arrayBuffer()`, `new Response(body, { status, statusText, headers: response.headers })`, `cache.set({ maxAge: SIXTY_DAYS })`, return it; (3) anything else → `cache.set(false)`, return as is. A short comment: Cloudflare-only, single `cache.set` call per request, why buffer (V2 tags land late).
**Files**: src/middleware.ts
**Verified**: `npx prettier --check src/middleware.ts` → pass. `grep -n "cache\.set\|private, no-store\|arrayBuffer" src/middleware.ts` → every line sits after a `context.cache.enabled` guard (reviewer reads it). `npx dotenv -e "$CFENV" -- npm run build:cf` → exit 0. ## Order

T1 → T2 → T3, in sequence: T2 needs the provider of T1 for `cache.enabled`, both run `build:cf` into the same `dist/`, and T3 deploys their result. The gate (`npm run lint`, `npx dotenv -e "$CFENV" -- npm run build`) runs after T2 and covers Done 5 with T2's `build:cf`.
